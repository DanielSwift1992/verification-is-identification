# Context names v1

These finite questions extend the existing context reader with supplied module re-exports and qualified nominal heads, including the ground generic applications supported by context/2. An actual `@_exported import` supplies an export edge. Its transitive closure extends each source's declared imports. An ordinary import in another module supplies no export edge. The context still binds each original input and hash; the source view resolves nominal identities before definition reduction.

A local declaration and an imported declaration can have the same short spelling. `M.N` selects N in the available module M. Two imported candidates used without qualification refuse at the reference. Two declarations in one module refuse at their source addresses. Bare alias cycles refuse at the alias declaration. Existing unqualified collision admission remains unchanged where no source supplies qualification and no imported reference requires an ambiguity choice. A qualified generic application requires context/2, exact declaration arity and applicability grounds. Declared bounds use the existing generic membership derivation through an unconditional conformance; a missing path refuses. Bound parameters/axes and module qualifiers spanning lines remain outside this extension. This is a fragment of Swift name resolution.

The internal nominal symbols are fresh relative to every supplied read view. Their serials distinguish declarations; their module/name suffixes identify them in diagnostics. They are not declarations added to the source or aliases supplied by an operator. Original source bytes, contexts and their hashes remain the input roster. The same scalar identity used by the common Court lexer keys module edges and declaration identities.

`contract.json` is read by the existing `Checks/court-contract.py` law. Its compiler plan assigns exactly the judged source files to named modules and a primary module. The driver checks that assignment against the context, emits the borrowed modules, then typechecks the primary files. Every prerequisite must exit 0; the primary exit and addressed diagnostics are recorded alongside the Court exit and answer. The minimal re-export question deliberately has no judged equality: its legacy answer is unsupported/empty demand, and its complete context/2 answer is `empty`, never `holds`.

The native compiler judges the declared equalities and conformances. The manifest driver is physical-runner debt: matching this finite suite is not a proof of complete Swift equivalence. The reader's export/binding projection is source-reader debt; see the T0105 removal entry in `Contracts/Checks/context-names-v1.md`.
