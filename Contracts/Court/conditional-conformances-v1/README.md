# Conditional conformance lists

`extension T: A, B where C` declares two independent gates with the same source owner, generic scope and condition C. The common Court notation reader expands the list on its existing lexical tape. It introduces no source declarations and performs no name lookup. ContextNameBinding supplies each full declaration identity before the bound view is read. Where and count-question discovery consume that same reading. Discovery declares questions; it does not establish the conformances or the numerical answers. The protocol-condition closure is shared by context preparation and uncontextual gate evaluation; splitting a list into singletons does not drop an inherited protocol condition.

Each protocol in a newly admitted list carries its source line and structural place `extension[n].conformances[k]`, with zero-based indices in read source order. The extension index counts all extension headers in the admitted view, after the existing conditional-compilation omission. This address identifies one protocol even when several occur on the same line; it is not a character column of the rewritten view. Context binding preserves the original place. An unsatisfied gate, including conditions inherited from its protocol, reports that protocol's place. An unknown qualified protocol refuses at its original name reference. Single-protocol addresses retain their existing format.

`contract.json` declares three exact complete reports: a qualified positive list, a list whose Plain gate holds but Fenced gate fails at `conformances[1]`, and an unknown `Base.Missing` reference. The native compiler checks the same source modules. `ConditionalConformanceTests` additionally checks count-question discovery, replayed ownership and the unknown-reference refusal in that entry. The original context-names-v1, count-bindings-v1 and bound-questions-v1 contracts are unchanged.

Other conditional syntax remains in the existing finite fragment: protocol declarations without a plain inheritance list, function-type conjuncts and other unjudged conditions do not acquire a verdict from admitting comma-separated protocol names. Qualified owners and references still need their existing binding derivation. The source-to-reading projection and the correctness of the procedural reader remain debt T0105-R/T0136; these finite observations are not a proof of equivalence with all Swift or of non-expressibility in the medium. Execution of the contract host remains debt T0105-C.

For inventory, `CourtNotation.readFile` exposes the ordinary independent file-reading phase with its original DocumentFile projection and lent attributes. `NotationScope.unreadDeclarations` collects the locally decidable declaration-shape refusals using the same guards as ordinary admission, and returns diagnostics only. Ordinary admission still throws its original first error; no partially admitted scope is returned by the diagnostic entry. Lexical/brace failures can stop that phase, and a refused file has no subsequent binding/application verdict. An inventory of these refusals does not establish the absence of later semantic obstructions.
