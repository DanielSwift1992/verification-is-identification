# Court questions 0.5 · original sources, shared notation, generic applicability

The initial 44 cases are frozen before the v0.5 owner implementation. Their normative questions are in `stages/claude-1-4-b1-b3.json`; `contract.json` binds that case set and all original input bytes. The owner and each port must answer these finite questions and retain v0.1–v0.4 compatibility. New source-context behavior is selected explicitly by context/2 and `--report`; it does not silently reinterpret the legacy CLI or the selected-applications v1 interface.

The changes: original bytes precede DefinitionView; a world may contain several own sources; module resolves an import while namespace identifies its declarations; the closed Swift/2 intrinsic exports exactly Never and String; generic membership requires actual-argument substitution into declared bounds and where conditions; count uses the common qualified-name/context notation; where shares source-derived expression and proof nodes instead of expanding repeated arithmetic subtrees. Plus, Twice, Times, U* and Scale* receive no built-in equations. Same count does not mean same nominal type. The normalization canon stays 4; the bounded graph construction and replay retain the previous where limits of 10 000 construction work and 20 000 replay work, with depth 64. No budget is raised to pass a world.

`--context path.json --report` reads vi.court.context/2. Every source has input, source, sha256, module, namespace, role (own or borrowed), imports and an at object containing an address for every scalar and every import. No source may claim intrinsic module or namespace Swift. The closed intrinsic has version vi.court.intrinsic-swift/2 and exports [Never, String], each with provenance. Context/1 and intrinsic/1 retain their old meaning. The explicit repeatable `--document path.swift` option selects the owner DefinitionView for a particular own source; unlisted own sources retain application-coverage reading. Every listed path must be a distinct own source. This option is a reading request, not a gate Kind imported into the notation-independent context.

Every own source is judged separately by where, with all other original sources visible as definitions; none are concatenated. Every excluded value-body view identifies its first excluded line per source as unchecked. A source with no checked obligation is empty, never holds. Count retains its all-presented-files question, including negative readings placed among definitions; its response attributes readings to each supplied source. The count-rule body check receives the original borrowed primitive bytes, even though declaration/name reading uses the shared view. A changed Unit/Never/Plus rule cannot be hidden behind DefinitionView.

For generic membership, a concrete actual argument that fails a declared bound or where condition is refused admission. A rigid argument whose required membership is not established is not-established. The generic head's name alone supplies neither admission nor a proof of its gated obligations. Unsupported conditions, unavailable definitions and circular grounds remain unsupported. A successful dependent membership discharges the instantiated generic conformer's gated protocol requirements as well as its applicability; it does not assume the conformance it is trying to establish.

The response is one JSON object and one LF on stdout, with no stderr. Its schema is vi.court.sources/1. Exact top-level fields: schema, question (where or count), inputs, outcome, results, diagnostics. Inputs contains the exact requested source paths and original SHA-256 values, plus the explicit context file; it is sorted by path. Results is sorted by input path. Each result has exactly path, source, outcome, equalities, memberships, readings, unchecked, diagnostics; counters are nonnegative integers. Where covers exactly the own sources after successful context admission, including empty and unsupported results. Count covers every supplied source. A global admission error has no results and names the error in diagnostics. Each diagnostic and unchecked entry is a string; an unchecked body is never counted as a checked obligation.

Aggregate precedence is unsupported, refused, not-established, holds, empty; holds requires a positive checked count, and empty requires zero checked counts without a stronger outcome. Exit is 0 for holds, 1 for refused/not-established, and 2 for unsupported/empty. JSON keys use deterministic lexicographic order; strings retain Unicode and slashes, and counters have integer spelling. The contract checks the complete input hash roster, exact result coverage, status/exit consistency, mandatory fields and the frozen case-specific outcomes, diagnostic fragments and lower bounds. Swift/native Rust/wasm must additionally match all response bytes exactly. This does not treat a summary status or an exit code alone as evidence.

The large-expression pair checks both sharing and the nominal distinction. Unknown equal spellings, recursive definitions and ungrounded membership do not become holds by a shortcut. Failure of the resource bound remains unsupported, with no inference of impossibility. Per-source results are not durable attestations: reuse at the gate boundary still needs the complete input/question/reader hash and the owner-side checking receipt. Scale's publication and live invalidation policy belongs to the subsequent integration, not to this court contract.

Eight subsequent audit twins are frozen in `stages/argument-ground-and-conditional-scope.json` before their repair: membership performs full nominal reduction as well as head reduction, so a retained cyclic or unreadable argument cannot supply a ground; an excluded conditional block keeps its source address in unchecked. This preserves existing alias reduction, which can erase unused arguments, and does not claim complete Swift validity. The initial 44 cases and their stage bytes are unchanged; this stage brings the candidate to 52 cases. A permitted flag block is a disclosed scope exclusion, not proof of its hidden claims.

Three all-source count controls are frozen separately in `stages/count-borrowed-coverage.json`: a context with only borrowed sources can hold or fail count, and an empty own file cannot hide a false borrowed reading. The source role is not changed to obtain a notation view. Together the candidate has 55 cases.

## Count binding projection · T0125

The context/2 count entrance consumes the very `WhereContext.prepare(notationOnly: true)` projection whose T0105 binding derivation has been replayed. Each declaration place includes its module and lexical owners; a reference names that place, its source position and visibility grounds. Fresh nominal symbols are the existing injective transport of those places into the reduction view. The numerical IR reads this bound view's structural productions and lexical nested owners; it never merges original declarations by their short spelling and never selects another owner. Original `File.text`, source hashes and context addresses remain separate from `File.view`. The original primitive bodies are still checked before any count equation is used.

This is the finite T0105 source/name fragment followed by the existing numerical fragment: closed source aliases and admitted-view metatypes carrying `PredicateReading`, exact selected Predicate/Encoding/Sigma, supplied Unit/Never/Plus definitions, head/field/alias reduction and signed 64-bit counts. Closed negative aliases among borrowed definitions remain in the all-input question. Excluded implementation regions remain addressed as unchecked; the court does not interpret arbitrary getters, value execution, generic-dependent reading applications or all Swift. Ambiguous visible references and unknown declarations/members refuse through the shared reader at their source addresses. The legacy flat count entrance and its finite rules are unchanged.

`count --report --context ... --bindings proof.json` replays the same ordered per-own-source `vi.court.context-name-bindings/2` derivations as `where`. Coverage, source/view hashes, declaration positions, scopes and target places must agree before numerical evaluation; the submitted proof is included in report inputs. Without this option a fresh derivation is replayed. Reduction and arithmetic then construct and replay the existing shared DAG against one immutable source, with the existing budgets, source definitions and operand/answer checks. Binding replay chooses no replacement reference; numerical replay chooses no replacement equation. Correctness of the common source/view transport and these procedural replayers remains the named T0105-R premise/debt; the finite contract is not a proof of general Swift equivalence.
