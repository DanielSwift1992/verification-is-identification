# Archived substitute for historical where checks

22 October 2026. This archive freezes 42 executable consumers (38 FiniteContinuation JavaScript files, three top-level JavaScript files and one Python file), plus one separately discovered native consumer. The original N4 list counted 43 files because it also included `Checks/README.md`; that document's original hash is retained as provenance only, and its prose may be corrected. [manifest.json](manifest.json) records the pre-migration vi revision and the before/frozen executable hashes. Historical `Research/Artifacts` receipts remain unchanged.

## Two different readers

[judge-where.js](judge-where.js) is a byte-for-byte copy of `bin/judge-where.js` at [gate@cd5c55750b4639e15136ded0592920c573ad89ce](https://github.com/DanielSwift1992/gate/blob/cd5c55750b4639e15136ded0592920c573ad89ce/bin/judge-where.js), immediately before [deletion 78c603c16406fd780942f5f73be72aa54293e8c0](https://github.com/DanielSwift1992/gate/commit/78c603c16406fd780942f5f73be72aa54293e8c0). Its SHA-256 is `3beed68f0ec30c7a2ca233b9754adfeb905a1502146129211bd4b51c62c67185` (20,587 bytes). `judge-cli.js` is a local wrapper for historical `judge where`, loading those same archived bytes. Neither requires a sibling checkout or a network connection.

**This archive is not the reader of the historical receipts.** The 207 JSON receipts in local `Research/Artifacts` identify SHA-256 `9d64a7db35ca82eb043f82702d8386dcc389cd7e90218f7ed6084c7317ed4088` (25,161 bytes). The manifest records this separately as `recorded_reader_sha256`, with a relative file address, file hash, JSON parent pointer and relative key suffix for each JSON receipt. Another 14 QPY payloads contain the same reader hash and are not addressed here. The public declaration omits machine-specific key prefixes. There are 1,103 occurrences of this hash across those files; one pointer per file is retained. The receipts are local research evidence and need not be present in a fresh worktree. The independent Opus review identified their reader as an uncommitted version with no matching gate revision. Its private bytes are not included or published. Under the selected preservation decision, the public `cd5c5575` archive remains a deliberately different reader, and does not supply a replay of the recorded results.

The distinction changes actual answers. With the recorded reader, the independent review ran `four-contact-court.js`, `contact-boundary-court.js` and `local-policy-court.js` against the preserved source question: all returned exit 0, reporting respectively 134 obligations with 9 substitutions refused, 8 equalities with 3 substitutions refused, and 6 equalities with 3 substitutions refused. With the archived reader, all three return exit 1: the first two reject positive obligations, and the third returns exit 1 instead of the expected reader-limit exit 2. **These red archived runs result from substituting the reader, not from source drift.** The previous explanation was incorrect. No source requirement was weakened to make this substitute pass.

Both readers use canon v2; a canon number does not establish byte identity or truth. The archived reader accepts all five original Court v0.1 comparison cases, whereas current source-replayed canon v4 accepts two and refuses `same-count-different-tree`, `twice-opaque-name` and `twice-definition-is-identity`. The independent review found the same three false acceptances in the recorded reader. Migrating to current Court therefore requires a separate review of the historical claims and premises. Neither canon-v2 reader certifies new claims. New code uses `Sources/Court` and its versioned contract.

## Integrity boundary

`python3 Checks/archived-where.py`, registered in `check.sh`, verifies the archived reader, 42 frozen executable consumers and the additional native consumer. It also preserves the separate recorded-reader identity and the 207 receipt addresses. The manifest has a closed top-level key set; each receipt has exactly `path`, `sha256`, `matching_pointer_count`, `json_pointer_parent` and `key_suffix`. A parent is either the empty root pointer or slash-separated container names matching `^\w+$` individually: encoded separators, tildes and filesystem paths are refused. Extra fields at either of these two levels are refused. `Checks/README.md` is outside the executable hash checks. All `Checks/**/*.{js,py,sh}` files are scanned case-sensitively for these specified spellings: a literal `..` followed by one or more slash/backslash separators and lowercase `gate` (including shell assignments, commands and template strings); a Python single identifier followed by a `.parent` chain or `.parents[N]` with a nonnegative integer, then `/` or `.joinpath(` and a quoted lowercase `gate`; Node `path.join`/`path.resolve` with a first argument consisting of word characters, dots or dollar signs, then one or more quoted parent arguments whose exact content is `..` or slash/backslash-separated repetitions of `..`, then a quoted lowercase `gate`; and the old reader override. Node parent arguments with a trailing separator, a computed first argument such as `path.dirname(__filename)`, and case variants such as `Gate` are outside this scan. This bounded spelling scan does not model filesystem case folding. The component boundary excludes word characters, dots and hyphens: `gateway`, `gate.js` and `gate-tools` are allowed. New undeclared users of the archived reader are refused; the archive implementation and its control harness are explicitly identified. These are checks of declared bytes and specified literal path spellings, not a complete analysis of arbitrary path computation. The integrity gate does not require the local receipt files or read any private reader bytes.

`python3 Checks/archived-where-test.py` injects sibling paths in nested JavaScript, IBMBridge Python, top-level Python and shell files, multiple Node parent parts, template strings and Python indexed-parent/joinpath constructions. It also tests the override, changed reader/consumer bytes, an undeclared archive consumer, a substituted receipt-reader identity, a missing receipt address, home-relative and user-directory parent encodings, an extra receipt field and an extra top-level field. Positive controls permit neighboring `gateway`, `gate.js` and `gate-tools` module names and a correction to `Checks/README.md`. Changing the archive requires an explicit new declaration and review; a green integrity gate does not establish the truth of canon-v2 conclusions.

For an explicit diagnostic run: `node Checks/four-contact-court.js`, `node Checks/contact-boundary-court.js`, or `node Checks/local-policy-court.js`. An optional first argument selects a historical native Tools binary for comparison; current Tools does not promise agreement with canon v2. The three archived programs remain red for the reader-substitution reason above. Larger historical programs retain their own inputs and limits. This task does not authorize a mass rerun of experiments, hardware access or replacement of saved results.

`returning_night_audit.py`, absent from the original N4 list, formerly selected a sibling native executable. It is separately frozen in `related_native_consumers`: it now requires an explicit `VI_ARCHIVED_NATIVE_TOOLS` and still checks that binary against its historical receipt hash before execution. The binary is neither supplied nor rebuilt here.

The §1 connection is explicit ownership and provenance: vi no longer silently reads a neighboring checkout, and the next reader can distinguish the public archive from the reader actually named in the receipts. This engineering change does not advance §12 or alter a mathematical result.
