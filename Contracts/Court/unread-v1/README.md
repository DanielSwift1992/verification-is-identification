# Unread gated applications · v1

The owner freezes 46 complete CLI observations from the accepted T0098 merge named in contract.json, before changing application discovery (44 initial cases and two ICU word-boundary neighbors frozen before correcting that projection). Each case binds its UTF-8 sources and the exact exit, stdout and stderr of `judge where`. The cases include qualifications and their start addresses, alias propagation, nesting, metatype line breaks, comments, literal content and interpolation code, declaration exclusions, borrowed inputs and Unicode/CRLF neighbors. These are finite regression observations, not a proof of lexical correctness or a general cost bound.

The repair changes discovery, not the relation judged: every application of a gated head outside a read span or a declaration header is reported. The ordinary declaration reader, alias closure, reduction and semantic judgments remain separately responsible for their inputs. No consumer names or task records determine this mechanism.

`SourceLexing.lexicalScan` emits `NotationToken` while it emits the blanked notation view. This is a projection of its decisions, not another lexer of Swift. In particular, executable interpolation is kept even though the blanked text no longer has its backslash; literal contents and comments are absent. The projection retains the old notation's exact `\w` and `\s` classes and UTF-16 coordinates: two constant scalar-class expressions use that same backend, with a fixed ASCII table and a per-scan non-ASCII cache. Swift Unicode properties are not substituted for the backend's classes; they differ on some private-use scalars even on the measured host. Neither expression depends on a name or scans the source. The existing conditional-block projection filters the same tokens and remaps their offsets with the same retained lines. Structural token identity and admission do not change.

`UnreadHeads` indexes scalar-exact name components in reverse order once for the judgment. `unreadApplications` advances through each file's tape once, carries the earliest admissible qualification start, and advances one sorted covered-span cursor. At `<`, a backwards walk through contiguous qualified components finds all indexed suffix names; a word chain can precede only one such `<`, so all these walks together visit at most the tape's words. Each angle frame is pushed once and removed once at its closing `>`, a brace, a semicolon, or EOF. The old arrow, declaration-header and multiline-metatype predicates are retained, including the distinction between Unicode whitespace in qualifications and ASCII whitespace before `.self`. Diagnostics retain their old sorting and addresses.

Let B be the kept UTF-16 length, T the tape length, S the number of supplied spans, M the total scalar length of indexed names, and P the number of emitted applications. Subject to expected constant-time dictionary lookup per hashed component and amortized array append, discovery costs O(M + B + T + S log S + P); diagnostic ordering additionally costs the comparisons for sorting P messages (O(P log P) comparisons, with message-length cost). Every component hashed in a tape lookup is charged to its spelling length. Storage is O(M + B + T + S + P). The bound is about discovery, not all of `where`: declaration reading, alias reachability, term reduction and membership judgment still contribute their own costs. No linear bound in the number of task records, no fixed response time and no adversarial hash-table bound for the whole court follows from this replacement.

The three XCTest methods run the frozen CLI observations, the relation between the shared lexical projection and qualified/interpolated applications, and loop-work bounds under added unrelated names, nested uses and overlapping covered spans. These controls can refute the implementation; the loop argument above, with its named collection-cost premises, supplies the asymptotic claim. Process execution, timing and corpus transport remain the physical-runner debt T0084; none of these checks encodes a consumer's subject matter.
