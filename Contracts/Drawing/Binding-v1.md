# A world binds the drawing roles

`DocumentKit` supplies `Paint`, the `LegibleOn…` constraints and the composition readers. A world supplies the paints and faces. `Diagram`, `GrownDiagram` and the caption/arrow forms that read fixed roles require `Binding: DrawingStyle`; its axes have no defaults. Shapes whose fill is already an associated type keep that explicit hole. Outline figures carry their measured faces and paints through their existing world theme.

`drawing-binding/1` is a data record. `name` identifies its Swift projection. `roles` maps role names to `light` and `dark` paint readings; an optional `variable` names the CSS property explicitly. `registers.BodyFace` and `registers.CaptionFace` supply the faces. `shadow` supplies paint and opacity; `leafCountBases` states additional opaque count bases. A producer may retain source/witness metadata alongside these fields. There are no executable providers or callbacks.

A role may declare `fallbackLight` and `fallbackDark` when its native standalone SVG reading differs from its host CSS reading. These fields preserve an existing representation explicitly. They do not supply a missing world binding. The company owner checks these readings by compiling its `Pulse.swift`; its CSS readings come from the same native `Palette` bindings and count equalities as the profile. Documentation vi uses the pinned gate readings directly, with no separate fallback paint. Its text surfaces are paper.

`Scripts/drawing-binding.py` projects the record into Swift atoms and a `DrawingStyle` conformance. It also projects the shared footer template at `Sources/DocumentKit/Resources/footer.html`. The generated footer is a DocC artifact; the template is the single authored mechanism. Both owners check that their generated bytes reproduce. The vi owner reads its palette and registers from the pin in `Worlds/Documentation/figures.json`; `python3 Checks/documentation-binding.py --write` updates its binding and both documentation footers.

A gate drawing profile names `Style` as a regular carried input row. Its owner receipt carries `result.binding` and `binding_row`; gate checks their equality to that input. If the record names `fallbackOrigin.row`, that source is another declared, hashed profile input. The native owner checks its readings before issuing the receipt. Both serve and publication carry this record to the same JS reader. A canvas without a delivered record refuses at `file#root`; a declared root `Binding` must match the delivered name. Earlier source worlds can receive their binding from the explicit profile input while their native SDK is migrated. A profile without `Style` grants no drawing style. `NoDrawing` uses its existing path.

The native fixture suite supplies its own binding, purple paint and measured Inter source. Seven SVG readouts are compared byte for byte with the JS port, and four native refusals keep their codes. Missing native `Binding`, missing or mismatched port records, removed count grants, literal role paints or faces in the mechanism, and changed binding inputs have separate negative controls. These checks cover the installed drawing subset; they do not establish full Swift interpretation or a new font rendering claim.
