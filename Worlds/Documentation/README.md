# vi figures

Four DocumentKit worlds own the method, framework architecture, three-source example and construction law. `figures.json` declares nine roots, output paths and Lit/Dim themes. README and DocC keep their image addresses, titles, descriptions and view boxes. `ThreeSources.swift` keeps the claims mapped in [beam-study-sources.md](../../Documentation/Figures/beam-study-sources.md).

Run `python3 Checks/vi-figures.py --write` to regenerate the projections. The `artifacts` law runs the same reader in comparison mode. It compares every generated byte and the complete input hash. Changed input/output bytes, missing glyphs, substituted font sources and unproved text/background pairs refuse with an address.

The style source is gate at the full pin in `figures.json`: `stdlib/bench-palette.swift` and `stdlib/bench-registers.swift`. The same pin's `web/ui.html` carries the register rule, and `bin/drawing-fonts.json` declares the Inter file. These four inputs are fetched by path and SHA-256 and recorded in the input hash; no gate target is built. No showcase palette input remains in these worlds.

The register rule gives speech a sans face and data a mono face. Ink carries primary/established content; muted carries secondary content. Colour identifies verdicts and referenced names. Package names use KnownName, rather than the success colour of an unrelated verdict. An ambiguous answer has no additional gate colour; it is stated in words. A continuation instruction is speech, rather than a claim that an execution has succeeded.

Each label declares its `Register` once, and binds both `Font` and `Size` through it. The artifact reader derives the label table from those declarations, rather than maintaining a second text/register registry. It checks every emitted face, size and paint against that table. `Registers.swift` and its JSON receipt are projections of the owner's actual register types and count equalities. Sizes use the owner's tenths of a pixel. The SVG places separate single-line labels, so register leading is recorded without changing the world's baselines.

Inter comes from `Assets/InterVariable.ttf`, with the same hash as gate's font declaration. Plain and Firm use measured wght 400 and 600; other variation axes remain at their defaults. CoreText selects and verifies those instances and reads advances and outlines from their file-backed CGFont. DejaVu Sans Mono Regular comes from the pinned DejaVu 2.37 archive and shares its declared license. All 88 corpus characters are covered, and every measured mono advance is 1233 at 2048 units/em. Firm mono has no measured 600 face in this input; requesting it refuses instead of selecting another weight.

[CharacterSources.json](CharacterSources.json) assigns each character separately for the Sans and Mono faces. Sans uses Inter for 84 characters; exactly four absent signs use DejaVu Sans Regular. Mono uses its own measured glyph for every character, including those four signs.

Every font file and license has a SHA-256 declaration. Each SVG embeds the two licenses and glyph source/weight metadata. The reader checks each glyph placement against its face's assignment and weight. There are no installed-font dependencies or system fallbacks. Outline generation requires CoreText; the SVG only needs paths.

Text stands on gate paper in both themes. All content panels therefore use paper; borders use line, and explanatory routes use muted. Mist has no text witness and is not used behind a label. The reader checks all eighteen gate paper contrast equalities on the pinned declarations with vi's native count operations, then checks each label's actual painted panel. A mutation from paper to mist refuses. Palette and register files use separate native scopes because both declare their own number ladder. Their compilation context imports vi and supplies the nominal `UnaryArithmeticEncoding` atom; no property of that atom is inferred. The checks establish the stated count equalities, not a new encoding theorem.

`Package.swift` and the target graph are unchanged: DocumentKit depends on Notation and Alphabet. The owner data cache is `.build/figure-inputs`; unavailable or changed bytes refuse at repository, revision and path. Palette and register readings do not introduce a build dependency on gate or showcase.
