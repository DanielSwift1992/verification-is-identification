# Press · substitution and replay contract 0.2

The question is a transition of one declared slot under an explicitly named chord of linear triples. The complete input is `arguments`, UTF-8 `state` and `dictionary`, their two diagnostic paths, and an ordered optional array `definitions: [{path,text}]`. Imports do not fetch definitions. A missing declaration needed by a bound is an addressed refusal before publication. Unbounded triples retain free structural atoms; this contract does not assert compilation of the resulting Swift program.

The owner is `Sources/Court/Press.swift`. Its declaration and lexical reader is `StructuralSource`, also used by `ApplicationCourt`; its complete term reader and simultaneous substitution are `DefinitionReduction`. The old `Press.Term` adapter remains for existing court clients; the unused permissive `Press.parseTerm` has been removed; `Press.Term` and `serialize` remain for those clients. Rule names are identities, comments cannot supply or override an alias, and an unread term suffix cannot be an atom. The selected enum must contain exactly the three nongeneric aliases `Slot`, `From`, `Into`. A slot is a constant name, with the existing `Slot` suffix convention; the state is exactly one nongeneric top-level alias of that name, and no other nominal or alias of that name may occur anywhere in the dictionary or definitions. A second place refuses at its own path and line even for unbounded triples. Only its RHS byte interval is replaced. Public aliases, semicolons, whitespace, nested comments, multiline terms, CR, LF and CRLF are read by the shared grammar. Carried bytes outside that interval remain identical.

Generic parameters occurring in From are bound by the linear match; the others are supplied in declaration order by `Rule<...>`. Every declared bound and where equality is substituted before the transition and submitted to the existing application calculus. Its single Derivation has an exact set of root goals and one checked dependency graph; roster membership, root applications and Press bounds all use this representation and replay. Membership uses its conformance, prerequisite and reduction rules. There is no Press alphabet or company membership table. The selected rule's declared bounds are established; arbitrary constraints on its Into expression and executable members are not proved. Rule-declaration compilation, when required by a consumer, is a separate question.

`contract.json` registers 132 named input/result cases, including the five hostile classes and legal neighbors, and supplied-certificate attacks. `Checks/press-contract.py` binds the manifest and all fixture bytes, checks exact state bytes, addressed refusals, and the replay flag where declared. The fixture suite is regression evidence, not the admission argument. The general argument and its premises are in [calculus.md](calculus.md). Revision 2 retains the original 52 cases and adds 11 named reading forgeries (F7c, H3, G1–G4 and leading-comment variants in state/definitions) and ten legal comment neighbors. Integration adds duplicate-slot-place and separate-slot-place: an alias beside a same-named nominal is ambiguous; a different declared name is its legal neighbor. These observations do not establish the general argument; in particular the former induction omitted its base, allowing F7c and H3.

## Certificate and replay

Successful linear applications and lawful no-ops return `certificate` and `replayed: true` through `Checks/press-contract/main.swift`. `Press.apply` calls `Press.replay` before returning; the native command prints the certificate after its status line. The public library replay method accepts a certificate and the complete input plus proposed output. In the JSON adapter, a request with `certificate` and `output` invokes replay only, without finding a match or deriving a bound. Malformed JSON is a transport error; a semantic replay failure returns unchanged input and an addressed refusal. A refusal is non-admission with an address, not a proof that every interpretation of the source is inconsistent.

`vi.press.linear-certificate/1` carries invocation, ordered input hashes, reading certificates, slot and half-open UTF-8 byte interval, an entry for every chord member, and optional selected index. Each entry names the rule and sigma, and either a constructor-disagreement path or a finite application-calculus proof of its substituted bounds. A disagreement path uses argument indices, and `-1` for a field's owner. The empty path denotes a disagreement at the root; a nil path denotes a complete match. The checker verifies all members and rejects more than one match. It checks old = From[sigma], new = Into[sigma], instance bindings, complete variable coverage, bounds and the entire proposed output, including carried bytes.

Each input hash is SHA-256 of `u64be(path.utf8.count) || path.utf8 || u64be(text.utf8.count) || text.utf8`, without Unicode or newline normalization. The ordered input list is state, dictionary, then definitions. Reading certificates contain lexical words with raw-byte ranges and top-level grammar-production token ranges. Replay compares them with the judgement of the complete original input by the accepted T0084 scanner and the one strict production reader, from byte zero to EOF. This includes the leading-comment induction base; submitted intervals cannot restart comment state. Reconstructed declarations feed StructuralSource(readings:), not a decoded AST or a second declaration parser. The given reader/replayer's correctness is an explicit premise; its procedural P4 debt remains T0084. Certificate JSON is not canonical byte output: set and graph enumeration order is immaterial to replay.

The reader claims the declared structural fragment, not all Swift. The shared `@resultBuilder` declaration annotation is carried without claiming builder execution. Unknown attributes and unknown top-level forms refuse. Press and roster can carry direct raw literals, including escaped delimiters; raw interpolation is conservatively refused. Extended regex and a non-comment slash without following ASCII whitespace refuse throughout the input, including carried bodies and ordinary interpolation. The non-roster token/projection paths retain main's refusal of all raw literals, as does the Rust structural port. This does not admit a top-level value or a literal member of a selected triple. Roster uses the same declaration grammar and separately restricts its member/carrier relation. Balanced bodies outside the selected triple remain carried syntax; their value semantics are unchecked, with their token and byte intervals retained by the declaration production. The shared grammar's lexical and local production rules are part of the given court, not an external compiler or a printer round-trip. A future change to that grammar must preserve or explicitly version this reading relation.

## Carriers and remaining work

The unchanged v0.1 suite remains required and its 33 expectations are not rewritten. Literal append/rubout/clear retain v0.1 behavior; they return no linear certificate. Their declarative replacement, including the alphabet/segmentation premise, is explicitly the unimplemented step B of T0083. No universal P3 claim is made for that legacy route. Its line-based lookup can edit a commented `typeName` (review reproduction L1); this is an unfixed reading defect, not admitted behavior. The separate top-level parser has been removed: init consumes FileReading from the same production driver. The historical structural projection explicitly carries conditional/executable regions, while Press and roster request strict declarations. The unproved procedural reader and full declaration-place binding remain debts, not external exceptions; see calculus.md. In particular, the free structural atoms of unbounded v0.1/v0.2 triples have not silently acquired declarations or membership facts.

The browser carrier in gate remains pinned to v0.1 and has not been repaired in this vi-only change. Its separate reader, ignored bounds, slot-as-pattern extension and absence of replay are the port debt recorded under T0083 in the desk package. A v0.1 pass is not a v0.2 claim. There is no Press implementation in the Court Rust sample; its where/count port is a different question. No wasm Press equivalence is asserted.

Run `bash Checks/press-contract.sh` to compile the same Court sources once for the adapter and run v0.1, v0.2, driver controls and native host controls. Explicit bound definitions for the native command are repeatable `--definitions <path>` inputs. No ambient module lookup, sibling checkout or network is used by Press.

Integration on T0084 retains all 73 earlier input/verdict observations and adds the declaration-place pair. Diagnostic substrings for forged reading tapes/production partitions now name disagreement with the whole-source judgement instead of the removed sliced lexer. This unreleased v0.2 manifest is resealed explicitly; v0.1 bytes and expectations remain unchanged. The F7c/H3/G1–G4 inputs and their refusal outcomes are retained.

## Revision 3 input boundary

The unreleased v0.2 revision adds 57 named observations: N3a/N3b/N4/rx2 in every input role, their comment neighbors, twelve old-probe certificates, BOM/native parity, duplicate places with and without bounds, and literal-boundary neighbors. Native state, dictionary and definitions use WhereJudge.fileText: invalid UTF-8 refuses and a UTF-8 BOM is preserved. A BOM then receives the same addressed unread-token refusal as JSON and roster. This is a named conservative false refusal: Swift accepts a BOM, but this declared fragment does not. No unedited state bytes may disappear at the transport. Legacy literal editing still has its separate L1 debt.

The scanner recognizes delimiters by Unicode scalars, retaining original UTF-8 coordinates and one newline for CRLF; this prevents a combining scalar from hiding punctuation inside a Character. The historical structural projection now refuses an unattached @resultBuilder (including on class; enum/struct remain supported). This is a tightening from main, not a claim about Swift builder validity. Multi-file reading errors retain the offending input's path, line and byte. Raw-literal refusal in non-roster structural/token/projection paths is restored to main and no Court Rust class expansion is claimed.

Revision 4 supersedes the lexical split described in revision 3: WhereJudge and StructuralSource now project one lexical judgement. notationFiles/NotationScope and CountCourt.blocks still have separate production readers; that remaining P4 T0084 debt is not closed by sharing the lexer.

## Revision 4 shared lexical judgement

WhereJudge.lexicalReading is the sole delimiter/state machine. WhereJudge.blankCommentsAndStrings projects its blanked text; StructuralSource.scan projects its original-byte addressed tape. The complete table of implemented form families and declared refusals is in calculus.md, with 43 rows and 172 mode decisions read directly by SourceLexingTests. The table includes conditional-production refusals of stripComments, attribute lending and macro shadowing; it is not a proof that the procedural reader implements all Swift. No second table of expected lexical decisions lives in the test. The contract manifest binds calculus.md as well as the Press cases.

Strict Press/roster reading refuses a code directive at any depth, including carried member bodies and ordinary interpolation. A hash inside a comment/string is content; directly delimited raw carriers retain their declared support. All modes refuse backquoted identifiers, including SE-0451 identifiers containing quotes or comment delimiters. H1a/H1b, H2a–c, H3e/H3f and H8 each have an apply refusal, a preserved old honest certificate that must now refuse, and a comment neighbor. The v0.2 suite now has 156 cases; 61 are native controls (90 including v0.1 and publication controls). H8 is an escaped single-line newline that Swift itself rejects, not a valid-Swift counterexample; the common lexer now refuses it too, with LF and CRLF decisions in the table.

The structural projection used by judge apply, coverage and continue --relations is tightened from ed1852dd: unspaced division such as 8/2 and extended regex such as #/a/# now refuse instead of being carried. Sharing the notation lexer also makes backquoted identifiers and unrecognized attributes/macros refuse there, including inside carried bodies. H8 refuses in every mode. These are named conservative class changes, not evidence that those valid Swift forms lack meaning. Ordinary spaced division remains a lexical neighbor. The already declared resultBuilder class restriction and raw-literal refusal in structural projection remain; no broader Court Rust/wasm class parity is claimed by the existing finite Court suite. Conditional omission in historical projection remains its separate production policy, not a new claim that it selects a Swift compilation.

CountCourt compares primitive body shapes from the already read token tape. It no longer prints a token body and lexes that synthesized text again (which inserted whitespace between an attribute marker and its name). This changes no arithmetic primitive or admission equation. The leading-comment base, complete-input replay, whole-input slot uniqueness and byte-preserving native transport remain required. The literal editing route and full declaration-place binding remain the previously declared debts.
