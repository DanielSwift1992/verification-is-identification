# World drawing binding

`drawing-binding/1` is an ordinary pinned owner input. Its `roles` supply paints for each theme and an optional portable sRGB projection, `registers` supply faces, `layout` supplies the named measurements, `shadow` supplies its paint and opacity, and `leafCountBases` supplies opaque one-leaf readings. A layout row has either a textual reading or a Swift type expression. Native Swift compiles the expression; the JS port reads its existing arithmetic subset. Missing readings refuse by binding field and world root. An unavailable expression remains outside the port's supported subset.

DocumentKit declares the names and mechanisms. `DrawingStyle` requires associated `Values`, `PaintValues` and `PaintFallbacks` structures beside its typed face and paint axes. The common projector writes their immutable `typeName` readings and native numerical compositions. `StyleValue` and `DeliveredSVG` are type readers; each reading derives from the selected owner projection. The SDK has no selected style or ambient binding.

The owner can supply a generated companion with `--aliases`. It binds SDK vocabulary such as `EdgeMargin` and `TextXS` within the compilation context and supplies `StyleBound.Binding` there. The world's source and imports remain the same. Each such compilation context selects one owner; explicit bindings can be compiled together without installing global companion aliases. The companion and its source JSON are declared context inputs. Paint names in the SDK are CSS slots with no selected colour: a library may forward them before choosing its owner. DeliveredSVG resolves them through PaintValues at the reading root, while the shared footer declares the same slots for HTML. A missing companion leaves abstract style names and a missing binding at the compiler's source address.

`DrawingPalette` is the shared role vocabulary for figures. Its foreground/paper pairs have an owner `LegiblePaintPair` whose proof has the two numerical sides. Native labels check that equality. The figures bind those roles to the pinned gate palette; the generic contract fixture takes the same owner palette and registers. Register and glyph projections are checked against their pinned and measured inputs.

The portable SVG attribute precedes the owner's exact CSS paint in the style declaration. Values come from the binding. The Swift and JS readers use the same delivery rule. Owner profile receipts carry the exact binding and its input row, so serve and publication select one record. The reader does not construct a company palette or execute a generator.
