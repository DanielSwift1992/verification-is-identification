# Boundary law

`python3 Checks/dependency-boundary.py` checks the finite vocabulary and exact declarations in `Checks/dependency-boundary.json`. This repository owns the executable law in `Checks/boundary-law.py` and its counterexamples in `Checks/boundary-controls.py`. Another repository can consume those files by commit and SHA-256 while supplying its own root, CONFIG and POLICY_SHA256. The law does not import a consumer's format or names.

The policy lists the source scope, selectors and exact fixture paths. A selector can restrict its paths or capture a name only in a declaration context. Ordinary prose is not a reserved subject vocabulary. Repository references include SSH and schemeless owner/repository spellings. Style selectors include six-digit colors with an optional alpha pair. DocumentKit is an owned module; its name is restricted only at consumer-target selection paths. NUL-containing payloads contribute their filenames, but are not decoded as source. A non-NUL file that fails UTF-8 decoding refuses with a path, line and byte offset.

Within `Checks`, the temporary-evidence selector matches the literal lower-case token `private/` at a word boundary and the quoted lower-case component `private` immediately after a slash operator on the same line (with optional whitespace). It covers these spellings in tracked or unignored source and filenames, including nested directories; the policy catalogue itself is excluded by the shared law. Ordinary `private` access modifiers and `privateer/` do not match. Computed paths and other spellings are outside this finite selector. T0073 removes these occurrences by passing the evidence root and hash manifest explicitly; its removal task remains in the policy even when no debt row remains.

Debt entries name a removal task and reason. Exact declarations separately identify navigation without behavior, frozen contract inputs or explicitly pinned inputs. These declarations are reviewed policy, not a way for new code to authorize itself. The policy seal covers vocabulary, scopes, declaration identities and fixture membership; line addresses and opaque SHA-1/SHA-256 values do not change an occurrence's identity. The actual input contracts still verify those bytes.

Each debt occurrence must exist in the frozen source revision. Every reachable historical ledger also limits any occurrence its policy recognized. A reviewed selector extension can recognize a previously unseen occurrence in that frozen source; it cannot restore debt retired under an older selector. A previously approved exact reference can become debt under review. These rules apply through merges and require full Git history; shallow history refuses. The law neither fetches history nor rewrites it.

When code removes an occurrence, delete its debt row too. When only addresses move, run `python3 Checks/dependency-boundary.py --refresh-addresses`; this changes line numbers only and refuses other changes. When an approved declaration is edited, review its new meaning and exact row, then run `python3 Checks/dependency-boundary.py --policy-digest` and place the candidate value in the wrapper's POLICY_SHA256. That command prints a digest; it does not approve the change, edit the seal or authorize new debt. Rerun the law and controls after review.

`python3 Checks/dependency-boundary-controls.py` exercises changed input bytes, every scope root, ordinary prose, declaration contexts, invalid encoding, stale debt, declaration resealing, address refresh advice, source-ceiling growth, a real committed retirement and restoration, policy extensions and shallow history. The full gates execute both commands. This is a finite lexical boundary, not a proof that arbitrary new words or obfuscated encodings have no domain meaning.
