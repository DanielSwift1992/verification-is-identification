# Source line breaks · questions suite 0.3

The law owner reads the same declared relationships with LF, CRLF or CR line endings. These are Swift's three `line-break` spellings ([language grammar](https://github.com/swiftlang/swift-book/blob/main/TSPL.docc/ReferenceManual/LexicalStructure.md#whitespace-and-comments)). Before lexical or structural interpretation, the reader maps CRLF to one LF and then bare CR to LF. This is `vi.court.source-lines/1`. Original input bytes and their hashes are not rewritten. Diagnostic line numbers count logical lines. Term normalization canon 4, nominal equality and the Unit/Never/Plus question are unchanged.

The earlier Swift refusal on CRLF was an implementation defect: its Character-based alias boundary and structural token readers compared with LF alone, whereas CRLF is one Character. The Rust scalar reader happened to accept CRLF but did not consistently treat CR as a line boundary. Copying the Swift failure into Rust would have preserved a bug rather than the owner's declared question. This release fixes the source view in both implementations. It does not turn lexical agreement into proof of the source's claims.

The 38 finite cases contain LF/CRLF/CR/mixed twins for a true and a false nominal equality, a true and a false count, a changed Primitive body, and an unsupported conditional at logical line 3, and a plain excluded flag whose scope disclosure must remain. Ten further cases keep VT, FF, NEL, LS and PS inside a single-line comment before a fake macro. Promoting those scalars to a newline would expose that macro and fail the case. This does not define all Unicode input behavior or expand the supported term fragment.

Each fixture is bound by its exact bytes. `.gitattributes` disables checkout text conversion for this directory; the driver refuses a changed hash before running the court. v0.1 and v0.2 remain frozen. Their output transport rule (CRLF to LF on stdout/stderr) is separate from this source-line rule. Expected good/false answers come from the prior suites; primitive and conditional refusals retain their stated cause, with logical line addresses independent of physical line-ending bytes.

Run `Checks/court-contract.py --manifest Contracts/Court/v0.3/contract.json` with the same `--command-json` interface as prior releases. `Checks/court-contract.sh` runs all three. With `--compiler`, the twelve nominal/conditional twins also require the existing Swift typecheck outcomes. Build each carrier first; run all releases, internal proof controls and `rust-sample/diff-court.py` against native Rust and the wasm Node loader. A browser execution remains a separate check. Agreement here does not establish whole-language equivalence.
