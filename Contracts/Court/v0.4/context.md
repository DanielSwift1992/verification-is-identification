# The Court source context · vi.court.context/1

This optional input belongs to the law owner. It accompanies `judge where WORLD [DEFINITIONS ...] --context CONTEXT.json`. Its vocabulary is source, namespace and imports, independent of the notation of the supplied sources. It is not a declaration table or an intermediate representation. The scope map is a separate input to a different reading and is neither accepted nor inferred here. Without this argument, the conservative borrowed-gate and foreign-extension refusals of v0.3 remain.

The JSON object has exactly `schema`, `sources` and `intrinsics`. `schema` is `vi.court.context/1`. Each `sources` entry has exactly `input`, `source`, `sha256`, `namespace`, `imports`, `at`. `input` is one exact CLI source argument; `source` is the original logical source address; `sha256` binds the unmodified UTF-8 bytes; `namespace` is the declared namespace; `imports` is an array of namespace names. `at` has exactly `input`, `source`, `sha256`, `namespace`, `imports`: the first four are nonempty provenance addresses, the last is an equally sized array of provenance addresses for the imports. Paths are transport coordinates, not namespace identities. Every supplied source is covered exactly once; duplicate inputs, extra entries, missing entries, wrong bytes, unsupported fields, repeated imports and missing provenance addresses refuse before judgment. Sources sharing a namespace do not gain permission to duplicate a declaration.

`intrinsics` is an array of closed declarations. The only accepted entry in this release has exactly `namespace: "Swift"`, `version: "vi.court.intrinsic-swift/1"`, `exports: ["Never"]`, and `at`, with nonempty addresses for `namespace`, `version`, and each element of `exports`. No SDK is read or fabricated. An explicit import of Swift requires that intrinsic entry and a declared import edge from its source. An intrinsic is not a supplied source and supplies no checked obligation. Unknown namespace exports are unsupported, not an open registry.

The context declares which namespaces may supply names to each source. A source's own namespace and its listed imports are its visibility boundary. The Swift notation reader checks that every explicit import is declared; only plain namespace imports are in this fragment. Renamed/selective imports and qualified foreign extensions remain unsupported. Where two different namespaces supply the same short declaration name, this version refuses the ambiguity rather than choosing by file order; general qualified module-name resolution is outside this version. Nested enum names admitted by N remain distinct qualified declarations inside their source namespace. A foreign extension must have one declared visible target; extending a typealias, a qualified nested type, or exposing private/fileprivate members across sources remains unsupported.

The source bytes establish actual declarations, generic parameters, fields, refinements and gate conditions. Context words establish none of those facts. A borrowed gate reached by the judged world is retained with its original address; its conditions and inherited gated-protocol conditions join the same obligations as a local gate. A missing protocol premise, unread conjunct, ungrounded cycle or false condition cannot become holds. Adding or reordering unrelated supplied files cannot choose a declaration or erase an obligation.

Provenance addresses are claims in this input, not authenticated attestations. The Court checks the context shape and its byte binding, and reads the declarations itself. Gate must derive every field from its manifest/Language/record entry, retaining that entry's address; no missing field is invented. Its translation controls establish that correspondence. The Court does not read the gate record format. The source context does not by itself certify Swift compilation, runtime behavior, private access reachability or a drawing.
