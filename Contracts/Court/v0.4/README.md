# Court questions 0.4 · nested names, intrinsic names and borrowed obligations

The 73-case suite is assembled from separately committed case sets: N/S first, then context/G. `contract.json` binds the exact inputs, expected CLI channels and case-set hashes. [ERRATA.md](ERRATA.md) names one explicit correction to a pre-release Paired expectation; the original stage remains intact. v0.1–v0.3 are unchanged. Passing this finite suite is not a whole-language or whole-program equivalence claim.

N reads non-generic nested enums inside non-generic enum namespaces, including their flat parameterless fields, as qualified declarations. It never flattens a member into file scope. Nested generic containers, nested non-enum kinds, local declarations that bind court-read names, and qualified extensions remain addressed refusals. Unused local forms outside the old reading remain outside it; the positive scope control is retained. Count explicitly refuses this newly declared nested fragment until its own structural reader can preserve those identities. Source-relative reduction canon 4 is unchanged: a qualified nominal identity is not an equation, and a field still unfolds only its actual owner's definition.

S reads only plain `import Swift`, whose closed intrinsic Swift/1 exports exactly `Never`. Other qualified exports and conflicting source declarations refuse. No SDK source or environment lookup is implied. Imported-but-unused names discharge no obligation. The selected-applications v1 route retains its original reader until separately versioned; the CLI notation fragment advances to vi.court.swift-declarations/2.

The old internal scope-negative world now returns a semantic refusal for `Use<Plain>` (exit 1), since `Namespace.Plain` is correctly read without being substituted for the file-scope struct. The positive scope fixture changes its unused nested `Local` from struct to enum to stay in the newly declared whole-input nested fragment; its four original membership obligations and the compiler checks remain. The unread nested struct is retained as an explicit negative contract case, rather than silently ignored. These are internal fixture changes, not edits to v0.1–v0.3.


G uses the [source context](context.md), an explicit file beside the original world and definition bytes. It establishes namespace ownership and import visibility, then obtains obligations from those sources. Borrowed value declarations are outside this reading, with the first excluded source line disclosed per file; local types or aliases hidden inside them refuse. The executable world keeps the original application-coverage checks. A qualified nominal used as an equality leaf asserts no conformance. A borrowed conformer used to ground membership enters the judgment, including its gated refinements and further membership dependencies; ungrounded cycles refuse. The all-gates question for conditional-head certificates is retained. Missing premises, false obligations and unsupported conjuncts cannot produce holds.

The complete pinned Primitive/Vector and Primitive/Core/Verdict/Seeing inputs are covered by positive, false and lost-premise questions. This does not establish all twelve playground worlds: their owner-authored Language contexts and gate translation are the subsequent 4а-2 integration, with separate receipts. It also does not typecheck Swift implementation bodies or execute Half's numerical precondition. The old false definition-equality/count questions remain in v0.1–v0.3; the Drawing contract retains runtime Half refusals.

A missing free definition cannot be admitted by comparing its spelling with itself. `C-missing-leaf` and `C-missing-borrowed-leaf` refuse missing declarations, while `C-opaque-leaf` retains unknown contents carried by an actual nominal declaration. The context checks the reached free references after respecting lexical parameters and associated types; an earlier false or unsupported obligation retains its diagnostic.

The context binds the original UTF-8 byte sequence, including a supplied BOM, before the reader constructs any notation view. The owner uses a lossless UTF-8 file load, checked by a byte round trip. The BOM-positive world and definition twins hold; a digest computed after removing the BOM refuses. Foundation text-file loading would silently consume that prefix and accept the wrong digest, so it is not the byte-binding boundary.
