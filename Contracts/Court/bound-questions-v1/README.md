# Bound count questions v1

Count discovery takes the admitted context binding projection used by numerical reading. Its selectors come from the bound `PredicateReading` declarations. A selector states a question; it does not establish a reading. Qualified extension owners are admitted by the same source-bound name certificate as where/count. A missing or ambiguous owner refuses at its source address.

Within a generic owner's body, `Self` denotes that owner applied to its own declared parameters. The binding projection carries those parameters into a qualified member term before either reduction representation reads it. `Self` without a lexical nominal owner refuses. The existing protocol-header and ordinary nominal-where admission boundaries remain unchanged.

`reference_revision` names the implementation commit that produced these answers. `contract.json` freezes ten native questions over five input sets, each with a Swift exit, complete source context and exact Court output. `Primitive.swift` is an immutable input copied from vi@aa21e829cc77ccc24d396c697e7c2cae152d20cc, `Sources/Notation/Primitive.swift`. The prior context-names-v1 and count-bindings-v1 releases remain unchanged. `CountQuestionBindingTests` also exercises discovery on these same source inputs and rejects missing input coverage and a modified binding certificate. These observations do not establish complete reader correctness or equivalence with Swift.

The source-to-view/owner/selector projection and the physical test host remain debt T0105-R and T0105-C in `Contracts/Checks/context-names-v1.md`; no proof of inexpressibility in the framework has been presented.
