# Structural projection boundary

The structural questions `judge apply`, `judge coverage` and `judge continue --relations` consume the same `StructuralSource` reading. Its admitted input excludes conditional-compilation directives (`#if`, `#elseif`, `#else`, `#endif`) inside a projected brace-delimited body, at any nesting depth. A directive refuses the entire reading with its source path, line and zero-based UTF-8 byte offset, before any branch-dependent brace can close that body. It does not create an excluded scope or a partial certificate. Unknown declarations whose bodies the projection only carries are subject to the same boundary.

The common `WhereJudge` lexer supplies code-directive occurrences and their addresses on its tape. An occurrence in interpolation code is attached to its enclosing literal token. Comments and literal contents do not supply such occurrences; no second scanner, regular expression or spelling search reads them. `StructuralSource` checks these occurrences during its existing balanced-body traversal. The common lexer still recognizes conditional tokens: it is the structural grammar that refuses their position in a body. Strict Press/roster already refuse every code directive; their admitted class is unchanged.

The existing top-level conditional-block exclusion is unchanged; this contract adds no exclusion. Built-ins such as `#line` and `#available` keep their previous lexical admission. This is neither a Swift compilation check nor a claim that every recognized body is executable. Top-level conditional scope, full Swift semantics and notation readers used by other questions are not extended here.

`contract.json` freezes 24 source inputs, their SHA-256 values, refusal addresses or admitted top-level exclusion counts, and three actual CLI questions. `h3f.swift` and `lib.swift` retain the original O1 bytes: the old projection could answer `judge apply 'Tick<LampOff>' lib.swift h3f.swift` from a conformance hidden in an inactive compiler branch. `queries.swift` supplies independently valid questions for the three commands, so neighboring inputs must still produce an application, a finite coverage proof and a constructed continuation. The native tests execute the whole table and all 72 CLI pairs; `VI_CHECK_BUILD_BIN` supplies the declared built Tools directory.

These finite controls check the implementation against the declared boundary; they are not a proof about all Swift programs. The structural reason for the refusal is that the finite reader has no conditional-compilation semantics and cannot infer a branch-independent declaration boundary by counting branch-dependent braces. Correctness of the common lexer and body traversal remains a named premise of the reading judgement.
