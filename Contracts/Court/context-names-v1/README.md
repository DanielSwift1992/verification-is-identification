These finite questions extend the existing context reader with supplied module re-exports and qualified nominal heads, including the ground generic applications supported by context/2. A local declaration and an imported declaration can have the same short spelling. `M.N` selects N in the available module M. Two imported candidates used without qualification refuse at the reference. Two declarations in one module refuse at their source addresses. Bare alias cycles refuse at the alias declaration. Declared bounds use the existing generic membership derivation through an unconditional conformance; a missing path refuses. The internal nominal symbols are fresh relative to every supplied read view. Their serials distinguish declarations; diagnostics recover the source spelling from the same projection. They are not declarations added to the source or aliases supplied by an operator. Original source bytes, contexts and their hashes remain the input roster. The same scalar identity used by the common Court lexer keys module edges and declaration identities.

The native compiler judges the declared equalities and conformances. The manifest driver is physical-runner debt: matching this finite suite is not a proof of complete Swift equivalence. The reader's export/binding projection is source-reader debt; see the T0105 removal entry in `Contracts/Checks/context-names-v1.md`.

## Binding derivation and replay

`judge where-bindings <sources...> --context <context.json>` issues an ordered array of `vi.court.context-name-bindings/2` derivations, one for each own source question. `judge replay-where-bindings <certificate.json> <sources...> --context <context.json>` checks every question and edge against the same byte-bound inputs. The commands also accept the report's `--document <source>` view selection. `judge where <sources...> --context <context.json> --report --bindings <certificate.json>` makes the ordinary verdict replay that supplied derivation before judging its demands. The proof file is included in the report's input hashes. Existing report fields and commands without this option retain their transport shape; a fresh binding derivation is replayed internally for every current name-resolution mode.

Each derivation names its selected own source and lists every source input/module/import row, original SHA-256 and admitted-view SHA-256, every indexed declaration place and position, and every selected nominal reference's view range, source line, owner chain and full declaration place. The declaration table supplies each target's address. Offsets explicitly refer to the line-preserving view, not to raw UTF-8 bytes erased by DefinitionView. The original source hash remains separately bound. Stored names, paths, kinds and written references use ScalarName; only serialization carries their strings. ContextNameBinding reads the common lexical tape. Its selected module bindings also drive WhereContextNames' rewriting; an independent nearest-owner choice supplies no result.

Replay requires complete ordered source/declaration/reference coverage and equality of each typed row against the source-derived relation. A redirected declaration, changed scope chain, omitted or added edge, changed source hash or changed view hash refuses before an equality can yield holds. `bindings.json` freezes one native-positive source question with a valid proof and seven adversarial proof mutations. Swift's source question stays positive; Court refuses the invalid derivation. This tests proof admission, not equivalence between Swift's acceptance and an untrusted certificate.

The binding relation and its verifier are part of Court. Their correctness, the common lexical judgment, and the admitted-view projection are premises of this verdict; issuing and replaying a derivation does not prove equivalence to all Swift name resolution. T0105-R retains that source-reader/correspondence debt. Physical execution and native-module correspondence retain T0105-C. The new typed derivation does not erase either debt by a finite test count.


Extension members belong to the supplied nominal owner, including when that owner is imported or appears later in the input roster. File-level owners are indexed from the shared lexical tape before extensions are visited. The existing CourtContext intrinsic export profile supplies intrinsic owners; their declaration rows name the profile rule, not a fictitious source file. Every member and scope must have a provided owner. The full SDK derivations have no orphan owner paths.

An associated slot has one declaration. One parameterless typealias in its protocol extension may define its default; the declaration's `definitions` array preserves that separate source site. A second default, two associated declarations, or two ordinary members of the same owner refuse. The binding replay compares these definition sites as well as declaration and reference rows. It does not add a default-witness reduction rule: reading a default's place is distinct from proving all uses of it. `extension-owners.json` freezes native positive/negative questions for imported members and protocol defaults. The four cases are observations of these relations, not a claim of full Swift extension lookup.

## Current finite language · revisions 3–4

All current modes, including context/1 and `where` without a context, require one visible declaration and refuse shadowing. Files without a context share one unspecified module; they supply no evidence of distinct imported modules. Historical releases record earlier results and are not the active language. Members are visible in owner bodies, in protocol inheritance and where clauses, and in extension where clauses. Ordinary nominal where clauses do not admit their own or inherited member names; the fragment refuses that form, including explicit qualification and a homonymous outer declaration. An inherited member and a module declaration of the same name are ambiguous; the refusal names both source addresses. A qualified reference selects its owner. A generic parameter belongs to its lexical declaration, including a function, and is not a member: `Owner.Param` refuses. Parameter collisions require renaming the parameter or qualifying the module type; they do not suggest `Owner.Param`.

The replayed binding relation supplies the reduction view. Rewriting consumes its selected declaration places and explicit member receivers; neither a bound-name exception nor a nearest-owner search supplies another choice. The common lexical declaration heads supply nominal declarations, function/alias parameters and alias ranges. Function overload scopes include their source-site identity. Alias-head cycles, including generic aliases, refuse at the alias source; import and re-export cycles refuse at the declared import edge.
