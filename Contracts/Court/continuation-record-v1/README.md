# Addressed worlds for U5–U8

This is the direct record entrance to the existing continuation calculus. Its implementation module, ContinuationRecord, has no package target dependency. RecordCourt depends only on that module. Court depends on it, not the other way around. The direct entrance reads no Swift text, StructuralSource, Context, declaration names or foundation signatures. The implementation language remains Swift. This is the U3 carrier with declared equalities and the U5–U8 question forms of §12; the physical carrier of §12 is not advanced.

## World schema 1

The record is a closed JSON object with exactly schema, source, equalities, observation and question, in that order. schema is the integer 1. No labels or payload values are admitted. Opaque sorts range over arbitrary nonempty sets and have nonnegative integer identifiers allocated in first-source-occurrence order, starting at zero. A repeated sort identifies a carrier, not two unknown contents. A place is its Left/Right path from the one Source root, encoded as an array of 0/1 sides. The root path is []. Names and content hashes do not identify places.

source is a nonempty flat list representing one finite ordered binary tree. Each entry has exactly one field: {"sort":n} for an unknown leaf, or {"pair":[l,r]} for its two child indices in the list. The root is entry zero. Canonical indices are preorder, visiting Left before Right. Each entry is used exactly once. A reference outside the list, a cycle, a repeated tree node and an unreachable node refuse with a source address. Repeated subtrees still have distinct occurrences. Finite cycles among declared equalities are allowed; these are not cyclic constructor trees.

equalities is a list of records with exactly at, left, right and basis, in that order. at is the distinct 0/1 address of the declared E-edge, retained by the existing E-path certificates. The list is sorted lexicographically by at, with a shorter prefix first. left and right address leaves of Source of the same sort. basis is exactly "declared": this is a conditional source premise at that edge, not a successful test of observed payloads and not proof that a physical equality was established. The court quantifies over every filling satisfying these premises. An absent premise is not silently supplied. Empty E is the explicit empty list. The existing certificate grounds remain distinct: the identical source address, a path through declared E-edges, and the refused observedValues ground.

observation and question are finite trees. A leaf is {"place":path}, addressing a Source leaf. A pair is {"pair":[leftView,rightView]}. A view may repeat or omit source occurrences. A bare sort, a nonleaf route or an address of another whole is not a source place. These trees are the U3 leaf maps of Observation and Question from that same Source. No leaf constant, payload test or independently sampled marginal is introduced.

For example, the following record asks for the right unknown from the left unknown of the same sort, without any E premise. It has a U5 obstruction and a one-leaf U6 residual. Adding the edge {"at":[],"left":[0],"right":[1],"basis":"declared"} instead gives a U5 construction.

```json
{"schema":1,"source":[{"pair":[1,2]},{"sort":0},{"sort":0}],"equalities":[],"observation":{"place":[0]},"question":{"place":[1]}}
```

The canonical serialization is precisely the ASCII UTF-8 line above, without a line terminator, spaces, escapes, BOM or extra bytes. The writer uses the declared key order, decimal integers without leading zeros, preorder node indices, first-occurrence sort numbers and sorted E-edge addresses. A tree and its ordered source/view roles are retained; canonicalization does not quotient places or prove semantic equivalence of different worlds. The reader checks the schema and addresses, then requires equality with this serialization. A correctly spelled but noncanonical transport also refuses with its first differing byte. JSON keys are checked for duplicates before insertion into a dictionary, including escaped duplicate keys. Invalid UTF-8, unknown fields, malformed integers, missing values and trailing input are addressed unread inputs. This finite JSON reader shares no Swift lexer or name resolver.

Admission currently bounds the input at 8 MB, the JSON reading at 100,000 values and depth below 128, the source tree at 10,000 entries, and paths/source/view depth below 128. These are named implementation resource boundaries, not theorems of impossibility. The existing U5 construction/replay also retains its 100,000-step E-path budget. An unread or exhausted input exits 2; it is never an obstruction certificate.

## World schema 2: total actions

Schema 2 keeps the five schema-1 fields, with schema = 2, then optionally actions, then optionally hiddenActions. Schema 1 has no such fields and retains its exact bytes. An absent actions means the empty G; an explicitly present [] also represents empty G but remains present in the canonical syntax. An absent hiddenActions means no U8 question. A present hiddenActions must be nonempty. H is checked independently; H need not be contained in G.

Each member has exactly at and image, in that order: {"at":path,"image":[sourcePath,...]}. at is the member's addressed identity retained in words and certificates, not a declaration name or its image. Members occur in strictly increasing lexicographic at order, with shorter prefixes first; the reader preserves that order and refuses duplicates or disorder instead of sorting them. Different member addresses may have the same image. Every image contains exactly one source-leaf path for every Source leaf, in Source's Left-before-Right order. Each selected source leaf must have the sort of the corresponding output leaf. The admitted tree of the action is rebuilt from that Source shape; a shorter image, a nested substitute, a nonleaf or a wrong sort refuses at that member's image address. This is a total structural T → T action over the same unknown source, with no payload constants or Swift aliases.

For example, the member below exchanges two same-sort Source leaves. With Observation = Question = Source, G generates a stable two-class view. The hidden singleton has a common action; replacing it with identity and exchange produces U8 disagreement.

```json
{"schema":2,"source":[{"pair":[1,2]},{"sort":0},{"sort":0}],"equalities":[],"observation":{"pair":[{"place":[0]},{"place":[1]}]},"question":{"pair":[{"place":[0]},{"place":[1]}]},"actions":[{"at":[],"image":[[1],[0]]}],"hiddenActions":[{"at":[],"image":[[1],[0]]}]}
```

The same ASCII canonical serialization and input/resource rules apply. The court checks preservation of declared E by each member and supplies E-path evidence or an addressed preservation refusal. It constructs the Question-class closure with addressed words, the stable view and decoder U7, then the common action or an outside/disagreement certificate U8 on Observation. With --actions, exit 0 means the G preservation/stable-view judgment and, if H is declared, a common H action; exit 1 is their verified refusal, including failure of E preservation. That preservation refusal does not assert impossibility after dropping the declared premise. A common k answers Question after a hidden action only if Question factors through Observation; this mode does not assert that factorization from exit 0. The joint source-dependent choice relation R ⊆ H × X_E remains outside this declared independent-family class.

## Construction and replay

```sh
RecordCourt [--retain|--actions] [--certificate proof.json] world.json
RecordCourt replay [--retain|--actions] proof.json world.json
Tools judge continue --record [--retain|--actions] [--certificate proof.json] world.json
Tools judge replay-continuation --record [--retain|--actions] proof.json world.json
```

The standalone executable and the Court facade call the same record entry point. Schema 1 selects U5/U6; schema 2 requires --actions and selects U7/U8. A schema/mode mismatch refuses. Image, Output and other unread axes are refused fields, not ignored extensions; U9–U11 and other courts keep their Swift entrance. The old --relations and type-field commands retain their meanings and bytes.

The existing U5–U8 continuation rules have one implementation in ContinuationCore, including ContinuationDynamics for U7/U8. The Swift adapter admits its source through Context and converts it to the same WholeReading/Reading; the record adapter admits schema 1 or 2 directly. Both use the same constructors for selections, source E-paths, the assembled Program, obstruction partition, exact class forests and missing Question classes. Retention selects one same-source leaf per missing class and uses the same U5 constructor on the joint Observation/M view. Replay checks the presented paths, partition/forests and decoder, without graph search, equivalence closure or construction. U5 necessity and the class proof establish the same structural leaf minimum as the original relations contract. This is relative U6 minimality, not a bound in bits, physical copying or recovery of an already unavailable field.

The source-language ReadProof and RouteProof envelope cannot describe a source that contains no Swift declarations. Record proof format 8 therefore wraps the unchanged RelatedConclusion and optional RelatedRetention or Dynamics payloads with the canonical input record as a UTF-8 string and format = 8. Schema 2 requires Dynamics and forbids retention. These are the existing U5–U8 certificate types and replay rules, not a second calculus. The record string binds the whole question and its declared premises to the same source used for replay. Replay compares it with the currently admitted record; it does not parse a Swift proof or search for a replacement. Formats 1–7 and all their archives are unchanged. The format-8 transport uses sorted, pretty-printed JSON as before; its reader checks complete JSON input, duplicate keys and that no unread fields disappear on decoding. Its envelope has depth below 256 and value-reading fuel equal to the input byte count, within the same 8 MB archive bound. A value consumes at least one byte. This separates proof-envelope overhead from the world's depth-128 and 100,000-value boundaries, so an admitted deep view is not rejected merely because its certificate has another wrapper.

Without --retain, exit 0 means a constructed U5 continuation and exit 1 means its verified obstruction. With --retain, exit 0 means a verified minimal same-source retention plan, including zero residual; the P-only obstruction remains in the certificate. Replaying a retention plan without --retain checks the plan but reports the original P-only obstruction. An obstruction archive without a plan cannot be replayed as U6. Exit 2 names unresolved admission, proof or resource failure. Construction prints a canonical certificate followed by LF; a --certificate file omits that print terminator. Record replay prints the checked input bytes, adding LF only when missing, without re-encoding the envelope; the source-language --relations entrance keeps its existing printing policy.

## Grounds and qualification

The conditional argument is the existing VI U3/U5/U6 argument: source paths identify occurrences; each E-path composes declared equalities; assembly yields the required Question. A closed partition and its forests certify exact E-classes. A missing class supplies the two-element obstruction, and each missing class must be retained by every adequate structural residual. The Swift input codec's coverage, admission implementation and the correctness of the common replay remain named premises. The module graph establishes absence of a source-reader dependency, not soundness of a codec or a physical source premise. Implementation qualification remains debt T0109/Qualification under P1–P5; no VC23a inexpressibility exception is claimed.

The separate [Lean Record checker](../../../Proofs/U5/Record/README.md) proves both canonical codec round trips for schemas 1 and 2 and connects actual world bytes to the existing proved U5–U8 checkers. Its `lake exe record-check [--retain|--actions] proof.json world.json` replays format 8 with the same 0/1/2 meanings. Its payload JSON decoder, IO and execution remain named premises; this does not prove the Swift implementation correct. Neither this entrance nor these proofs advance the physical carrier of §12.

For an admitted Swift reading, the bridge keeps every source occurrence address, each E-edge address and endpoints, and both view maps. First-occurrence sort numbering is a bijection on the sorts that occur in Source, preserving and reflecting sort equality. Interpreting a new sort by the same nonempty set as its old counterpart identifies the compatible filling families and leaves both views unchanged. U5 existence and U6's missing classes/minimum therefore transport under this renaming. This conditional argument does not establish arbitrary Swift admission, physical origin or the correctness of the implemented encoder; those remain separate grounds. Unused display names are not transported as source identities.

The differential observations cover every U5/U6 case of continuation-relations-v1, comparing judgments, missing E-class address sets and residual cardinalities. Admitted Swift readings are serialized by the shared canonical writer; unread Swift declarations have explicitly malformed record counterparts for the same rejected condition, rather than an invented admitted world. Those unread observations do not prove a semantic equivalence between arbitrary malformed texts. The original archives in every mode are checked separately. Native controls also distinguish two same-sort places, declared E, finite E-cycles, malformed pair cycles, duplicate keys, unread bytes, forged paths/partitions/residuals and replay against a substituted record. Tests are regression observations, not a proof of the reader or of all implementations of the calculus.

The T0117 differential compares all 17 action cases: 13 admitted records have equal verdicts and complete Dynamics payloads after first-occurrence sort numbering, including classes, words and stable views; four unread declarations have explicitly malformed counterparts. It does not claim equivalence of arbitrary malformed Swift syntax. Member addresses and complete images are transported directly by the admitted Swift adapter; source-shaped family splitting remains that adapter's job, while the record explicitly supplies member boundaries. The record path does not invoke that splitter, the Swift lexer or Context. Lean and RecordCourt replay checked bytes with the same LF policy, including compact or otherwise noncanonical certificate envelopes. Regression qualification and execution remain named debt T0117/Qualification and T0117/Execution; tests are not correspondence proofs.
